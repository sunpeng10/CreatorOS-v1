# CreatorOS Web implementation

The authorized design uses a dark navigation rail, a paper-colored research surface, teal actions, restrained editorial typography, explicit data provenance and honest empty states. Client-side authenticated views share same-origin `/api` requests; the API enforces all roles and organization boundaries. React renders all model/user content as text.

Implementation sequence: configuration and metric/security utility tests; reusable shell and forms; public/auth pages; upload and report workflow; library/recommendation/analytics/experiments; administrator CRM, services, approval and demo-order workflow; typecheck, lint, tests and production build. Root agent owns browser/API integration after these checks.

All operations persist through the documented API. Paid analysis requires a separate consent checkbox and user-selected budget. Missing AI or data stays visible. External links accept only HTTP(S). Client checks complement server upload verification.
