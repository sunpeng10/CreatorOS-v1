# 客户交互与服务订单闭环

目标：四张总览卡片支持悬停与明细弹窗；需求、回复、处理状态归属于真实注册客户；客户下单且老板接单后计入订单营收。

沿用 User、Lead、Ticket、Quote、Order、Delivery，不增加支付服务或拆分项目。订单营收代表已接单金额，界面明确尚未发生资金结算。历史模拟记录归档，保留备份与审计。

- [x] 关联：新增 customer_links.py，按完整、规范化邮箱匹配历史线索；运行时只认领未绑定记录。部署时按所有者本次授权修正错误历史绑定，同时调整对应工单、报价及订单，保留消息。新提交要求登录，拒绝填写其他账号邮箱。每个需求同步生成客户可见工单，保持状态可追踪。
- [x] 订单：客户 POST /orders 使用已启用服务的服务器价格，request_id 生成稳定报价 ID 防止重复创建。新订单 REQUESTED；老板接单变 IN_PROGRESS 并记 accepted_at；完成服务变 DELIVERED；客户验收变 COMPLETED。报价订单先 AWAITING_CUSTOMER，客户确认后才可接单。停用模拟支付入口，既有 is_demo 记录退出业务列表。
- [x] 统计：只统计关联有效 CLIENT_USER 的非模拟业务。按已接单且未取消的订单求和 booked_revenue，最近七天按接单时间统计营收。卡片明细直接使用同一查询返回的 leads/orders/pending approvals/cost events，避免数字与列表不一致。
- [x] 页面：Stat 增加可选点击；总览用现有 Modal 呈现限定高度的简洁列表。服务与反馈增加安静轮询及窗口激活刷新。官网需登录提交需求，服务卡跳转客户下单入口；订单页提供服务选择、确认下单、接单、完成服务、验收操作。报表移除模拟收入，展示订单营收、订单数、模型成本和估算毛利。
- [x] 验证与交付：先运行新增定向失败用例，再一次性执行受影响 API 用例并生产构建；不重复浏览器验收。备份数据库，修正历史绑定、归档模拟记录，在无活动分析任务时重启服务；更新 TEST_REPORT 与 OWNER_ACTIONS 后保存本地提交。
